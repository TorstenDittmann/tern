Native macOS browser · WebKit · Swift

A browser your coding agent can drive.

Tern is a fast, keyboard-first browser for developers. It's plain AppKit around WebKit, under 1 MB, and it ships a CLI and an MCP server so agents can open, click and read the same tabs you do.

Agent API

Let your agent test the thing it just built.

Turn on the agent API and Tern listens on a local socket. Agents get the page as a compact outline with a ref on every element, then click, type and read it back, in a real tab you can watch.

zsh · ~/shop
$ tern tabs open localhost:5173/checkout --wait idle
$ tern page snapshot
form "Shipping address"
  textbox "Email" e3
  textbox "First name" e4
  button "Continue" e7
$ tern page type e3 "ada@example.com"
$ tern page click e7
$ tern console read --level error
[error] POST /api/address 422 (postcode required)
$ tern network list --failedOnly true
422  POST  /api/address   38 ms
MCP · one line for Claude Code
$ claude mcp add tern -- \
    /Applications/Tern.app/Contents/Helpers/tern mcp
  • You can see what it's doing.A tab an agent is acting on gets a purple ring and an “Agent is driving” tag.
  • Real input, real logs.Clicks and key presses are real macOS events, so pages see trusted input. Console output, uncaught errors and fetch or XHR requests are captured per tab.
  • MCP without glue.tern mcp exposes the API as tools like page_snapshot, page_click and page_screenshot, which comes back as an image.
  • Local only.Off by default. It listens on a Unix socket created 0600 and opens no network port. You can limit agents to the tabs they opened.
Keyboard first

Reach anything without leaving the keys.

Every command has a shortcut you can rebind, in Settings or in a JSON file. Pages can't capture them, because Tern matches shortcuts before the page sees the key.

Split view

Your app, its docs and its logs, in one window.

Up to four tabs side by side, stacked or in a grid, with draggable dividers. Split from the top bar or drag a tab onto the page. Each pane is labeled with its host, and the address bar, find and ⌘W follow whichever pane you click.

Tab list

Tabs on the right, where long titles fit.

The tab list sits on the right, level with the address bar, so the bar can run the full width for long URLs. Pinned sites sit as tiles on top, and split tabs stay together in one block.

  • Filter from the keyboard with ⌘E.Type to narrow the list, ↑↓ to move, ↩ to open, ⌘⌫ to close.
  • Two hundred tabs cost about as much as one.Restored tabs are just a URL and a title until you open them. Background tabs idle for 15 minutes give their memory back, keep their history, and show a moon. The bottom bar shows what Tern is using right now.

Private by default

Ads and trackers are blocked before you change a setting.

EasyList and EasyPrivacy are compiled to native WebKit content rules, so blocking costs the page almost nothing. Third-party pings are dropped, and links lose their tracking parameters before they load.

Native

No Electron, no bundled Chromium.

Tern is plain AppKit around WKWebView. It uses the WebKit already on your Mac, and the tab list is a cell-reusing table view rather than a web page.

Get Tern

Build it in about a minute.

There are no signed releases yet, so Tern is built from source. You need macOS 15.4 or later, Xcode 16.3 or later, and XcodeGen.

Tern is early and moving fast. It's MIT licensed, and issues and pull requests are welcome.

Open the repository Report an issue
zsh
$ brew install xcodegen
$ git clone https://github.com/TorstenDittmann/tern.git
$ cd tern
$ make run       # build Debug and launch
$ make release   # optimized Tern.app
